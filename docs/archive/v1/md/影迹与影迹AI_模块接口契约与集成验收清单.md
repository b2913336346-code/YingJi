
# 影迹 × 影迹 AI

## 模块接口契约与集成验收清单

影迹 Android 个人版 · 可复制 Codex Prompt · 以真实代码和测试证据为准

# 1. 架构和数据所有权

两个功能是同一 Android 应用中的两个逻辑模块。是否拆成 Gradle module 由真实仓库结构决定；不要求为了形式强行拆模块。

| 数据/能力 | 所有者 | AI 允许操作 | 禁止行为 |
| --- | --- | --- | --- |
| 作品/分类/标签/评分/观看状态与时间/海报 | 基础影迹 | 按授权只读；用户确认后通过现有用例新增 | 直接写基础 DAO、复制作品库、清理原始数据 |
| 明确偏好、推断画像、纠错 | AI 模块 | 按授权更新、纠错、删除 | 把推断当成用户明确表达 |
| 推荐候选/历史/缓存 | AI 模块及许可数据源 | 验证、过滤、排序、按期限保存 | 模型编造候选、许可到期继续展示受限字段 |
| DeepSeek 凭据、额度与费用 | Worker 后端 | 经受控 API 使用 | 密钥放 APK/Git/日志，额度只由客户端控制 |

# 2. 建议的 Android 内部接口

以下是建议接口，不代表仓库已存在这些类。Codex 必须先按真实项目风格确认命名与包路径。

| 接口/用例建议名 | 输入 | 输出/职责 | 约束 |
| --- | --- | --- | --- |
| ObserveLibraryRepository | 授权来源配置 | 只读提供作品、分类、标签、评分、观看记录 | 不得绕过 Repository 直接写 DAO |
| ProfileRepository | 偏好、来源开关、纠错 | 画像摘要、版本、更新状态 | 明确与推断分开 |
| CandidateCatalogRepository | 查询条件、许可状态 | 候选与来源元数据 | 遵守来源授权与缓存许可 |
| RecommendationUseCase | 模式、输入、画像版本、排除条件 | 验证和排序后的候选 | 硬条件由本地执行 |
| RecommendationHistoryRepository | 会话/候选 ID/时间 | 历史、删除、过期清理 | 默认 20 次/30 天，许可更严时优先 |
| AddRecommendedWorkUseCase | 候选、用户确认、分类、可选标签 | 调用现有新增流程 | 不直接写底层表 |
| AiServiceClient | 最小请求、requestId、版本 | 结构化响应/错误 | 只调 Worker，不直连 DeepSeek |
| QuotaStateSource | Worker 响应 | 剩余额度、重置时间、任务状态 | 服务端为权威来源 |

# 3. Worker API 契约草案

正式路径、认证、持久化方案与供应商参数需在实现前确认。以下字段用于冻结最小接口，不代表现有 API 已实现。

| 方向 | 字段 | 规则 |
| --- | --- | --- |
| Request | schemaVersion、requestId | 版本化 schema；requestId 用于幂等 |
| Request | mode、userQuery | 模式用枚举；自然语言长度受限 |
| Request | profileSummary | 只发送当前任务必要且获授权的结构化摘要 |
| Request | profileVersion、sourceSettingsVersion | 拒绝/丢弃旧版本结果 |
| Request | excludeExternalIds | 限制数量，使用外部 ID 而非 Room 主键 |
| Response | requestId、status | 响应与请求对应，状态明确 |
| Response | recommendationHints | 仅意图/排序提示，不是事实候选 |
| Response | usage、quota | 用量与服务端额度信息，不包含密钥 |
| Response | error.code、retryable | 统一错误码，不返回内部堆栈 |

# 4. 错误映射

| 情景 | 客户端行为 | 重试/额度规则 |
| --- | --- | --- |
| 无网络 | 用有效缓存或本地候选；显示离线状态 | 用户可重试；记录底层请求 |
| 超时 | 有限重试并保持 requestId 幂等 | 最多自动重试一次 |
| 鉴权失败 | 显示安全错误，不暴露内部细节 | 通常不重试 |
| 额度耗尽 | 显示额度/重置时间，本地功能可用 | 不发起新付费任务 |
| 候选源异常/许可失效 | 仅用仍被许可的缓存，否则显示空状态 | 不能补造候选 |
| 模型格式错误 | 拒绝不可信输出 | 最多按策略有限重试 |
| 授权/画像版本过期 | 丢弃旧响应，按新版本重新计算 | 避免重复结算 |
| Worker 存储故障 | fail closed，提示暂不可用 | 不得无条件放行付费请求 |

# 5. 集成验收清单

- [ ] 基础影迹在不启用 AI 时仍能正常构建、启动和操作。
- [ ] AI UI 可用 Mock 独立演示首次引导、快捷推荐、推荐卡、历史、画像管理和错误状态。
- [ ] AI 不直接写基础作品 DAO；入库必须经现有新增用例。
- [ ] 用户确认后才加入推荐作品；分类必选、标签可选、海报仅本地选择。
- [ ] 重复候选不会重复插入或覆盖既有状态。
- [ ] 来源开关关闭后该来源不再参与画像重算。
- [ ] 画像来源授权与向 Worker 传输授权/最小化边界明确。
- [ ] 发送给 Worker 的摘要最小化，不含完整作品库和无关原始评价。
- [ ] 明确偏好和硬条件不会被模型建议绕过。
- [ ] 候选来源、身份、许可状态和缓存期限可追踪。
- [ ] 同一 requestId 重复提交不重复结算；额度/并发有服务端测试。
- [ ] API Key 不出现在 APK、Git、客户端日志和测试报告。
- [ ] 历史数量、期限、单条删除、清空和缓存失效规则正确。
- [ ] 清理 AI 数据不删除原始作品、评分、观看时间、分类、标签或海报。
- [ ] 旧画像/授权版本的迟到响应不会覆盖新状态。
- [ ] DeepSeek/Worker/候选源异常不影响原有作品管理。
- [ ] 所有核心用例实际执行到断言；未执行用例单独列出。
- [ ] 所有 P0/P1 阻断缺陷关闭；无虚构候选、未授权画像、误删原始数据等问题。
- [ ] 分别记录构建、单元测试、数据库迁移、UI/仪器测试和设备验收结果。
- [ ] MuMu 优先但非强制；替代设备测试要标明真实环境。

# 6. 数据库和迁移安全

- 新增 AI 表/字段前先检查当前 Room Schema 和迁移历史。
- 优先使用独立 AI 表，不随意修改基础作品表；确需修改需说明理由。
- 迁移测试必须保留作品、分类、标签、评分、状态/时间和海报引用。
- 迁移失败不得静默清空数据库或执行破坏性 fallback。
- 跨 Room/DataStore/文件缓存清理需设计幂等恢复；不得假设跨存储事务原子性。

# 7. 设备测试环境

优先尝试 `<MuMu安装目录>/nx_main/MuMuNxMain.exe`；确认存在后启动，使用 `adb devices -l` 确认 device 状态。MuMu 不是强制要求；不可用时可用实体设备、Android Studio Emulator 或其他可用模拟器。报告必须记录实际环境，替代环境不能描述成 MuMu 测试。没有可用设备时，设备测试标记阻塞/未执行，不能以 JVM 单元测试替代。

# Prompt I1｜模块集成验收

**所属层：** 基础影迹 + AI + Worker

**使用时机：** 两个模块各自通过阶段验收后。

```text
执行影迹与影迹 AI 集成验收。先检查 Git 状态与接口契约，不自动重写架构、部署 Worker 或发布 APK。
逐项验证：基础作品库不启用 AI 仍可工作；AI 通过定义的 Repository/Use Case 使用基础数据；推荐加入作品需用户确认并走现有新增流程；授权/最小传输/版本/缓存失效正确；Worker schema、requestId 幂等、额度与错误映射正确；候选源和许可可追踪；AI 清理不误删作品；断网、超时、额度耗尽和服务异常不影响基础功能。
运行构建、单元、迁移、UI/仪器与设备测试。优先使用 <MuMu安装目录>/nx_main/MuMuNxMain.exe；不可用可用其他设备并记录实际环境。每项记录预期、实际、通过/失败/未执行、证据与缺陷等级。未执行到断言不能判通过。P0/P1 未关闭不得建议通过。输出风险并停止等待确认。
```

# 8. 缺陷等级

| 等级 | 示例 | 验收原则 |
| --- | --- | --- |
| P0 | 数据丢失、密钥泄露、未授权传输、误删作品 | 阻断验收 |
| P1 | 核心流程崩溃、虚构候选、硬条件失效、额度可绕过 | 关闭前不通过 |
| P2 | 非核心可恢复问题 | 记录并排期修复 |
| P3 | 轻微视觉细节 | 记录，不得谎报已修复 |
