影迹基础应用

前端 UI 与本地数据层分离开发手册

影迹 Android 个人版 · 可复制 Codex Prompt · 以真实代码和测试证据为准

# 1. 目标与边界

本手册负责影迹原有非 AI 功能。它与影迹 AI 共用同一个 Android 项目和 APK，不是两个独立应用。前端 UI 与本地数据/业务层分开开发；个人版不要求新建独立云后端。

- 前端 UI：Compose 页面、导航、表单、加载/错误/空状态与交互。

- 本地数据层：Room、DAO、Repository、业务用例、迁移、图片本地存储。

- AI 首页、画像、推荐、DeepSeek、Worker 不在本手册范围。

- 保持已确认的黑白极简风格和现有功能，不擅自增加功能。

# 2. 基础功能范围

| 模块 | 范围 | 验收重点 |
| --- | --- | --- |
| 作品管理 | 新增/编辑/删除、名称、分类必选、标签可选 | 新增编辑规则一致、重复作品处理清楚 |
| 观看记录 | 想看/观看中/已看完、观看时间、补录、评分 | 状态和时间正确，重启后保留 |
| 分类/标签 | 管理、作品关联、数量统计 | ID/关联不串联，不因重复输入崩溃 |
| 检索展示 | 搜索、状态/分类/时间筛选、海报墙/列表 | 结果正确，页面一致 |
| 海报与设置 | 本地海报、我的/统计、默认排序与展示设置 | 不联网抓取海报，删除与引用一致 |
| 持久化 | Room、迁移、异常写入处理 | 不清空数据绕过迁移 |

# 3. 执行顺序

1. 先发送 B0 全局约束，再发送 B1 只读审查。

1. 审查结果确认后，先修复数据层，再做 UI 修改。

1. 最后执行基础功能回归，确认可独立运行后作为集成基线。

所属层：基础应用通用

```text

本次只处理影迹非 AI 基础功能。先阅读仓库中真实存在的需求文档和测试记录；不得提前加入 AI 页面、画像、推荐、Worker 或 DeepSeek。
```

所属层：只读审查

```text

检查 Git 状态、构建入口、首页/导航、作品新增编辑、分类/标签、搜索筛选、状态与观看时间、评分、海报本地存储、Room Schema/迁移、DAO、Repository、ViewModel 和现有测试。
输出：真实架构；已实现/部分实现/未实现/未知清单；需求到文件映射；未解决缺陷与风险；可运行构建/测试命令及实际结果；最小修复计划与验收标准。不得仅凭文件名猜测实现。未执行测试标记未执行。只交付报告并停止。
```

# Prompt B2｜本地数据层与稳定性

所属层：Android 本地数据/业务层

使用时机：B1 报告确认并批准修改后。

```text
只修复 B1 已确认的基础数据层问题。先列修改文件和迁移风险，再按批准范围实施。
检查 Room Entity/DAO/Repository 的写入和事务；分类/标签关联与唯一约束；输入 trim、空名称与重复名称处理；数据库写入失败的可见错误；本地海报文件与数据库引用一致性；旧 schema 到新 schema 的迁移。
禁止清空数据库、删除测试断言或重写无关模块。测试正常/空白/重复输入、快速重复点击、插入失败、重启持久化和迁移保留。报告实际测试结果并停止。
```

# 4. 基础应用交付门槛

- 核心流程有真实测试结果；未执行项明确列出。

- 迁移和重启持久化有证据，不以清库规避问题。

- 分类/标签关联正确，新增编辑与海报操作不破坏数据。

- AI 功能不属于基础应用验收范围。


## 与影迹 AI 的模型 API 边界

基础影迹以本地数据层为主，不直接调用 DeepSeek API，也不保存模型 API Key。DeepSeek API 只能由影迹 AI 的 Cloudflare Workers 后端代理调用。本文档是设计基线，不代表后端已部署。
