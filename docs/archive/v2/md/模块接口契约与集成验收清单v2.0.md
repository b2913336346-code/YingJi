
# 影迹 × 影迹 AI
## 接口契约与集成验收清单｜DeepSeek Android 直连 API 版

> 本版将模型调用更新为 Android HTTPS 直接调用 DeepSeek，不经过 Cloudflare Worker。本文是设计基线，不代表已实现。

# 1. 架构与数据所有权

| 数据/能力 | 所有者 | AI 允许操作 | 禁止行为 |
|---|---|---|---|
| 作品、分类、标签、评分、观看状态/时间、海报 | 基础影迹 | 按授权只读；确认后调用新增用例 | 直接写基础 DAO、复制作品库、清理原始数据 |
| 明确/推断画像、纠错 | AI 模块 | 按授权更新、纠错、删除 | 把推断当成明确偏好 |
| 推荐候选/历史/缓存 | AI 模块及许可数据源 | 验证、过滤、排序、按期限保存 | 模型编造候选、许可到期后继续使用受限字段 |
| 用户 DeepSeek Key | 用户本人/Android 密钥模块 | 加密保存、主动请求时读取、替换/删除 | 明文存储、写日志、提交 Git |
| API 费用 | 用户 DeepSeek 账户 | 请求前提示、本地用量估计 | 宣称本地软额度是供应商强制上限 |

# 2. 唯一调用链与安全约束

**Android App → HTTPS → DeepSeek API**

- Android 只访问固定的 DeepSeek 官方 HTTPS 主机，不经过 Worker 代理模型请求。
- 使用 `Authorization: Bearer <用户 API Key>`，不得放入 URL 或查询参数。
- endpoint、模型名、请求字段和响应 schema 必须在实现时核对官方文档。
- 不接受任意 Base URL，避免密钥被发送至非预期服务器。
- Key 不得进入日志、崩溃报告、错误消息或测试报告。
- 模型 API 与影视元数据 API 是不同接口；模型输出不是作品真实性凭证。

# 3. Android 内部接口建议

实际类名需按仓库确认，不要求机械照搬。

| 建议接口 | 职责 | 约束 |
|---|---|---|
| `SecureApiKeyRepository` | 加密保存、读取、替换、删除 Key | Keystore 支持加密，不写普通 Room 表 |
| `ApiKeyValidationUseCase` | 用户主动验证 Key | 最小请求，告知可能收费，失败不覆盖旧 Key |
| `DeepSeekApiClient` | 直连 DeepSeek | 固定 HTTPS 主机、Bearer 鉴权、脱敏日志 |
| `AiServiceRepository` | 提供 AI 任务状态 | UI 不直接发 HTTP |
| `ProfileRepository` | 画像、授权、纠错 | 明确/推断偏好分离 |
| `CandidateCatalogRepository` | 候选、来源与许可 | 验证外部 ID 和许可 |
| `RecommendationUseCase` | 过滤、排序、去重 | 硬条件不可被模型绕过 |
| `AddRecommendedWorkUseCase` | 加入作品库 | 用户确认后复用现有新增流程 |
| `LocalUsageTracker` | 本地用量/软额度提示 | 不得宣传为服务端强制额度 |

# 4. DeepSeek 请求契约

常见接口形态，实施前需核对官方当前文档：

- Base URL：`https://api.deepseek.com`
- Endpoint：`POST /chat/completions`
- Header：`Authorization: Bearer <用户密钥>`
- `Content-Type: application/json`

请求仅包含当前任务必需、已授权的上下文；模型和参数以账户权限及官方 schema 为准。响应需检查状态码、JSON/schema、输出长度。格式错误的模型输出不能直接变成已验证候选。不要将 Key、Authorization Header 或完整画像写入日志。客户端任务 ID 用于防止重复提交，不代表供应商保证计费幂等。

# 5. 失败处理矩阵

| 情况 | 客户端处理 | 重试 |
|---|---|---|
| 未配置 Key | 提示配置，不请求 | 不重试 |
| 401/403 | 检查 Key/权限 | 不自动重试 |
| 429 | 提示速率/额度限制 | 不循环重试 |
| 余额/计费错误 | 提示检查供应商账户 | 不重试 |
| 断网/连接失败 | 提示离线，可用合法缓存/本地候选 | 最多一次有限重试 |
| 超时/5xx | 显示暂不可用 | 最多一次有限重试 |
| 格式错误 | 拒绝不可信输出 | 不无限重试 |
| Key 删除 | 阻止新请求，尽可能取消在途请求 | 不再发起 |

# 6. 费用与额度边界

- 用户承担自己的 DeepSeek API 费用。
- 本地每日软额度（例如默认 30 次成功任务）可以被清数据、改时间或修改客户端绕过。
- 直连模式没有可信的 Worker 服务端计数器。
- 重试可能产生额外费用；防止重复点击并限制重试。
- 验证连接可能产生费用，必须在操作前提示。
- 不承诺客户端能保证用户账户不超支；用户应自行检查供应商账单/消费设置（如可用）。

# 7. 安全验收

- [ ] Key 不在源码、APK 常量、Git、普通 Room 字段、日志或报告中。
- [ ] Key 使用 Keystore 支持的加密方案保存。
- [ ] 网络仅 HTTPS，固定预期 DeepSeek 官方主机。
- [ ] 不接受任意 URL。
- [ ] 日志不记录 Authorization Header 或完整敏感请求体。
- [ ] 备份/恢复不会静默恢复无法解密的 Key。
- [ ] 更换 Key 验证失败不覆盖旧 Key。
- [ ] 删除 Key 后阻止新请求且不删除作品。
- [ ] 请求只包含已授权的最小画像摘要。
- [ ] 用户主动操作前不发起可能计费的请求。

# 8. 集成验收清单

- [ ] 不配置 AI Key 时，基础影迹仍可构建、启动、记录和管理作品。
- [ ] “我的 → AI 模型配置”符合黑白极简风格。
- [ ] 未配置 Key 时不发请求并提示配置。
- [ ] AI UI 可用 Mock 独立测试。
- [ ] 网络请求经统一客户端，不由 Compose UI 直接发 HTTP。
- [ ] 候选来自可验证且许可允许的数据源。
- [ ] 画像来源开关和传输边界明确。
- [ ] 明确偏好/硬条件不可被模型绕过。
- [ ] 用户确认后才将推荐加入作品库。
- [ ] 分类必选、标签可选、海报仅本地选择。
- [ ] AI 清理不删除作品、分类、标签、评分、观看时间或海报。
- [ ] 网络失败不影响基础影迹。
- [ ] 测试实际执行到断言，未执行项明确标记。
- [ ] MuMu 优先但非强制，替代环境记录真实信息。

# 9. 旧 Worker 迁移

- 先搜索现有 Worker 调用路径和配置，再决定弃用范围。
- 不因架构变更自动删除 Worker 目录或其他仍被使用的代码。
- 确认无其他功能依赖后，才移除旧模型代理调用。
- 本版不要求 Worker 接收或转发用户 DeepSeek Key。
- 若 Worker 仍用于其他用途，必须明确区分。

# Prompt I1｜直连 API 集成验收

执行影迹与影迹 AI 直连 DeepSeek 集成验收。先检查 Git 与真实接口，不自动重写架构、不部署 Worker、不发布 APK。验证唯一调用链 Android HTTPS → DeepSeek；BYOK 安全存储、固定官方主机、schema、错误映射、有限重试、费用提示、客户端软额度说明、画像最小化、候选真实性和用户确认入库。AI 清理不得误删基础作品；断网/超时/计费错误不得影响基础功能。自动化测试优先 Mock；真实 API 测试须先获得用户明确批准并告知可能收费。逐项记录通过/失败/未执行和证据。未执行不得判通过。MuMu 优先但非强制，记录真实环境。旧 Worker 调用先报告弃用项，不自动大范围删除。完成后停止。
