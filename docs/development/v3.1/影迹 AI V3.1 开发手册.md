
# 影迹 AI V3.1 开发手册
## BYOK 用户自带 DeepSeek API Key｜Android HTTPS 直连 API

> 本版取代“Android → Cloudflare Worker → DeepSeek API”调用链。模型请求由 Android 直接 HTTPS 调用 DeepSeek，不经过 Worker。本文只定义方案，不代表 API 已接通或测试通过。

# 1. 冻结架构

- 唯一模型供应商：DeepSeek。
- 调用链：Android App → HTTPS → DeepSeek API。
- 不使用 Cloudflare Worker 代理模型请求。
- 用户自带 API Key（BYOK），不提供开发者共享 Key。
- API Key 通过 HTTPS Bearer 鉴权，不得硬编码、提交 Git、写日志或存入普通 Room 表。
- 使用 Android Keystore 支持的加密机制保护本地密钥；加密降低静态泄露风险，但不能保证运行时密钥绝对不可提取。
- 不在设备本地运行大语言模型。
- 真实影视候选来自可验证且许可允许的数据源；模型输出不能单独证明作品存在。
- AI 请求失败不得影响基础影迹。

# 2. DeepSeek API 约定

常见接口形态，实施前必须核对官方文档：https://api-docs.deepseek.com/

- Base URL：`https://api.deepseek.com`
- Endpoint：`POST https://api.deepseek.com/chat/completions`
- Header：`Authorization: Bearer <用户的 DeepSeek API Key>`
- `Content-Type: application/json`

模型名、请求字段、价格、速率限制和响应 schema 以官方当前文档及账户权限为准，不得猜测。

# 3. 我的页面：AI 模型配置

新增“我的 → AI 模型配置”，保持黑白极简风格。

- 服务商固定 DeepSeek，V2.0 不支持其他供应商。
- Key 输入默认隐藏，提供显示/隐藏。
- 用户主动点击“验证连接”；验证可能产生费用，点击前提示。
- 验证成功后才能保存；更换 Key 时验证失败不得覆盖旧 Key。
- 显示未配置、验证中、已验证、验证失败和上次验证时间。
- 删除 Key 需二次确认；删除后阻止新请求，但不删除作品数据。
- 不回显完整已保存 Key。

# 4. 本地密钥安全

1. 使用 Keystore 管理加密材料，密文存应用私有存储。
2. 禁止明文 SharedPreferences/DataStore、Room 字段、资源文件、BuildConfig 和源码常量。
3. 日志、HTTP 拦截器、崩溃报告、分析事件和测试报告不得记录 Key、Authorization Header 或完整提示词。
4. 备份规则排除密钥及敏感配置；恢复后无法解密时提示重新配置。
5. 更换流程：验证新 Key → 成功后替换 → 清理旧密文；失败保留旧 Key。
6. 只有用户主动操作才发起可能计费的请求，不因打开设置页面自动调用 API。
7. BYOK 是用户自己的密钥，不是把开发者共享密钥放入 APK。

# 5. Android 网络层

使用统一的 `DeepSeekApiClient`/Repository（实际命名以仓库为准），UI 不直接发 HTTP。

- 固定官方 HTTPS 主机，不允许输入任意 Base URL。
- 通过 `Authorization: Bearer` 发送 Key；不放 URL 或查询参数。
- 建议连接超时 10 秒、读取超时 30 秒；根据实测调整。
- 瞬时错误最多自动重试 1 次；401/403、429、余额/计费错误不循环重试。
- 处理断网、超时、5xx、响应格式错误；限制响应体和输出长度。
- 使用任务 ID 防止双击重复提交，但不得声称供应商提供了计费幂等保证。
- 不记录完整画像、请求头或敏感请求体。

# 6. 画像与最小化传输

- 明确偏好与推断偏好分开。
- 个人评分、观看行为、AI 推荐反馈来源开关沿用已冻结规则。
- 只发送当前任务必需且已授权的结构化画像摘要，不上传完整作品库、无关评价、Room 主键或海报文件。
- 来源关闭后不得继续参与重算或模型请求。
- 画像/授权变化更新版本，旧响应不得覆盖新状态。
- 模型不得绕过硬过滤条件、用户排除项或数据源许可。

# 7. 影视候选与推荐

- DeepSeek 负责理解需求、分析画像、生成推荐方向/排序提示。
- 真实候选由已审核、许可允许的影视数据源提供，记录外部 ID、来源、元数据时间和许可。
- 先验证候选，再做本地硬条件过滤、去重和排序。
- 候选不足显示实际数量，不让模型补造。
- 用户确认后调用现有新增流程：分类必选、标签可选、海报仅本地选择。
- 不因接入影视 API 改变本地海报要求。

# 8. 费用与本地软额度

- 用户承担其 DeepSeek 账户产生的 API 费用。
- Android 直连模式没有可信的服务端请求计数器；本地每日软上限可被清数据、改时间或修改客户端绕过。
- 可将 30 次成功业务任务/日作为默认本地提醒，但必须明确它不是供应商强制额度或费用上限。
- 重试和重复请求可能产生额外费用；防重复点击并限制重试。
- 不承诺客户端能保证账户不超支；用户应查看供应商控制台的账单/消费设置（如可用）。

# 9. 故障降级

| 情况 | 行为 |
|---|---|
| 未配置 Key | 不发请求，提示前往模型配置 |
| Key 无效 | 提示验证失败，不覆盖旧 Key |
| 401/403 | 检查 Key/权限，不重试 |
| 429 | 提示速率/额度限制，避免循环请求 |
| 余额/计费错误 | 提示检查供应商账户 |
| 断网/超时/5xx | 最多一次有限重试；否则使用合法缓存/本地候选或提示失败 |
| JSON/schema 无效 | 拒绝不可信输出，不展示为已验证候选 |
| 删除 Key | 阻止新请求，尽可能取消在途请求 |
| AI 故障 | 基础作品库仍可用 |

# 13. TMDB 海报预览与本地保存规则（已冻结）

## 13.1 产品交互规则

1. AI 推荐列表可以在线预览 TMDB 海报。在线预览只用于显示，不代表已保存到本地。
2. 用户点击“加入影迹”时，只保存作品信息；不得自动下载海报。
3. 作品成功加入影迹后，用户进入该作品详情页，可主动点击“使用此海报”。
4. 点击“使用此海报”后先展示确认提示；只有用户确认后才开始下载。用户取消时不发起下载、不改变作品或海报数据。
5. 若作品尚未加入影迹，不能提前下载海报；应提示用户先加入作品。
6. 海报保存成功后，留在当前作品详情页，立即显示本地海报，并显示非阻断式提示“海报已保存”。不跳转页面、不要求用户再次确认。
7. 下载失败时留在详情页，保留作品和原有本地海报，显示明确错误及重试入口。
8. TMDB 后续更新在线海报时，不得自动替换已保存的本地海报。
9. 只有用户主动选择“更换海报”或主动删除时，才允许改变本地已保存海报。禁止后台静默下载、自动更新或自动替换。
10. 无 `poster_path`、图片加载失败、图片域名不可达或网络异常时显示占位图，不影响推荐结果展示和作品入库。
11. 海报文件保存到应用私有目录；Room 只保存项目定义的本地文件引用，不存图片二进制，也不得把在线 URL 写入本地路径字段。

## 13.2 在线来源与本地文件分离

- TMDB 的外部作品 ID、`poster_path` 和在线图片 URL 属于来源元数据。
- 现有作品实体的本地海报字段继续只保存本地文件引用。
- 不得为 AI 海报另建一套作品库或复制作品实体。
- 如果现有模型没有合适位置记录 TMDB 来源 ID/路径，先检查现有结构，再提出最小增量方案；不得擅自复用本地路径字段存在线 URL。

## 13.3 下载与数据库一致性

保存顺序必须如下：

1. 用户主动点击并确认保存。
2. 校验 URL 为 HTTPS，主机属于实现中明确允许的 TMDB 图片主机；拒绝任意 URL。
3. 下载到临时文件，设置连接/读取超时和文件大小上限。
4. 校验 HTTP 状态、内容类型、文件大小和图片解码结果。
5. 将验证通过的文件写入应用私有正式目录。
6. 正式文件写入成功后，再更新数据库中的本地海报引用。
7. 数据库更新失败时保留旧引用，并清理未被引用的新文件。
8. 新文件引用成功后才可考虑清理旧文件；删除前确认没有其他作品引用该文件。
9. 保存成功后刷新当前详情页状态，立即显示本地文件并提示“海报已保存”。

不得先删除旧文件再保存新文件或更新引用。海报下载失败不得回滚已加入的作品。对同一作品进行重复点击时必须防止并发保存。

## 13.4 状态与异常

- `NOT_SAVED`：本地没有海报，可主动保存。
- `DOWNLOADING`：正在下载/校验/写入，禁用重复提交。
- `SAVED`：显示本地海报和“海报已保存”；应用重启后仍显示本地海报，不自动联网替换。
- `FAILED`：作品和原有海报保持不变，显示错误与重试入口。

断网、超时、HTTP 错误、图片损坏、格式不支持、空间不足、文件写入失败、数据库更新失败或应用在保存中退出，都不得导致已加入作品丢失。

## 13.6 TMDB 数据接入与许可边界

- DeepSeek 模型请求与 TMDB 元数据/图片请求是两条独立链路。
- DeepSeek：Android App → HTTPS → DeepSeek API，使用用户自带 Key；不经过 Worker。
- TMDB：优先测试合规、可达的官方 API/图片端点；如确需代理，只能使用独立自建且受限的 TMDB 代理，不得接受任意目标 URL。
- TMDB 代理（如有）只处理 TMDB 请求，不得转发 DeepSeek 请求。
- TMDB 元数据、缓存期限、署名及图片使用须遵守适用条款；未核实许可状态不得标记为已确认。
